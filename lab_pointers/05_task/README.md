# Задание 5*. Зубчатые двумерные массивы

## Описание

Реализация «зубчатого» (jagged) двумерного массива как `int**` —
массива указателей на одномерные массивы. Демонстрация создания,
заполнения, вывода, перевыделения с сохранением данных и корректного
освобождения памяти.

## Файлы

- `matrix_utils.h` — объявления функций
- `matrix_utils.cpp` — реализации функций
- `main.cpp` — демонстрация работы

## Функции

| Функция | Назначение |
|---|---|
| `int** createMatrix(int rows, int cols)` | создаёт матрицу `rows × cols`, элементы = 0 |
| `void fillMatrix(int** matrix, int rows, int cols)` | заполняет по правилу `matrix[i][j] = i * j` |
| `void printMatrix(int** matrix, int rows, int cols)` | выводит матрицу построчно |
| `void freeMatrix(int** matrix, int rows)` | освобождает строки, затем массив указателей |
| `void resizeMatrix(int**& matrix, int& rows, int& cols, int newRows, int newCols)` | перевыделяет матрицу, сохраняя старые данные в левом верхнем углу |

## Ответы на вопросы

### 1. Почему нельзя просто написать `void f(int arr[][])` без размеров?

Компилятору нужно знать размер **второй и последующих размерностей**,
чтобы вычислять смещение элемента `arr[i][j]`. Для `int arr[][N]`
он знает, что строка занимает `N * sizeof(int)` байт, и может посчитать
адрес `arr + i * N + j`.

Если размер неизвестен, смещение посчитать нельзя → тип неполный,
компилятор откажется. Именно поэтому передают `int**` либо `int arr[][N]`.

### 2. Чем «зубчатый» `int**` отличается от настоящего `int[rows][cols]` в памяти?

- **`int[rows][cols]`** — один непрерывный блок `rows * cols * sizeof(int)`.
  Все строки идут подряд, элементы `matrix[i][j]` на расстоянии `i*cols + j`.

- **`int**`** — массив из `rows` указателей (`new int*[rows]`), каждый указывает
  на **отдельный** блок `new int[cols]`. Строки могут лежать где угодно
  в куче, между ними нет непрерывности.

`int**` позволяет делать строки разной длины («зубчатый» массив),
но требует отдельного освобождения каждой строки.

### 3. Почему при освобождении сначала удаляют строки, потом массив указателей?

Потому что после `delete[] matrix` мы потеряем массив указателей и уже
не сможем добраться до `matrix[i]` → утечка всех строк.

Правильный порядок:
```
for (i) delete[] matrix[i];   // сначала каждую строку
delete[] matrix;              // потом массив указателей
```

### 4. Что будет, если вызвать `delete[]` только на `matrix`, но не на `matrix[i]`?

Утечка памяти: все `rows` строк останутся выделенными в куче, но указатели
на них потеряются. Для больших матриц это может быть значительный объём.
Инструменты типа ASan/Valgrind сразу это покажут.

### 5. Почему в `resizeMatrix` используется `int**& matrix`? Можно без ссылки?

`int**&` — **ссылка на указатель на указатель**. Она нужна, чтобы внутри
функции **заменить** оригинальный указатель `matrix` в вызывающем коде
на новый.

Без ссылки пришлось бы возвращать новый указатель (`int** resizeMatrix(...)`)
и присваивать его снаружи: `matrix = resizeMatrix(matrix, ...)`.
Это тоже рабочий вариант, но в задании требуется именно ссылка.

### 6. Какие риски связаны с использованием `int**`?

- **Много ручного `new`/`delete`** → легко забыть освободить строки → утечка.
- **Фрагментация кучи**: каждая строка — отдельный блок.
- **Двойное освобождение** → `double free`, UB.
- **Использование после `delete`** → UB.
- **Исключения**: если `new int[cols]` упадёт в середине `createMatrix`,
  часть уже выделенных строк утечёт (нужен RAII).
- **Плохая локальность кэша** по сравнению с непрерывным `int[rows][cols]`.

В реальном коде рекомендуют `std::vector<std::vector<int>>` или
плоский `std::vector<int>` с индексацией `i * cols + j`.
