# Задание 5*. Зубчатые двумерные массивы

## 1. Почему нельзя просто написать `void f(int arr[][])` без размеров?

Компилятору нужно знать размер **второй и последующих размерностей**,
чтобы вычислять смещение элемента `arr[i][j]`. Для `int arr[][N]`
он знает, что строка занимает `N * sizeof(int)` байт, и может посчитать
адрес `arr + i * N + j`.

Если размер неизвестен, смещение посчитать нельзя → тип неполный,
компилятор откажется. Именно поэтому передают `int**` либо `int arr[][N]`.

## 2. Чем «зубчатый» `int**` отличается от настоящего `int[rows][cols]` в памяти?

- **`int[rows][cols]`** — один непрерывный блок `rows * cols * sizeof(int)`.
  Все строки идут подряд, элементы `matrix[i][j]` на расстоянии `i*cols + j`.

- **`int**`** — массив из `rows` указателей (`new int*[rows]`), каждый указывает
  на **отдельный** блок `new int[cols]`. Строки могут лежать где угодно
  в куче, между ними нет непрерывности.

`int**` позволяет делать строки разной длины («зубчатый» массив),
но требует отдельного освобождения каждой строки.
