# Задание 2. const с указателями и ссылками

## Описание

Реализованы функции, демонстрирующие различия между обычным указателем,
указателем на константу (`const int*`), константным указателем (`int* const`)
и константной ссылкой (`const int&`).

## Файлы

- `const_utils.h` — объявления функций
- `const_utils.cpp` — реализации функций
- `main.cpp` — демонстрация работы

## Функции

| Функция | Назначение |
|---|---|
| `void printValue(const int* ptr)` | вывод значения через указатель на константу |
| `void printValueRef(const int& value)` | вывод значения через константную ссылку |
| `void tryModify(const int* ptr)` | попытка изменить данные (невозможна) |
| `void setValue(int* ptr, int newValue)` | изменение значения через обычный указатель |

## Ответы на вопросы

### 1. Чем отличается `const int* p` от `int* const p`?

| Запись | Что `const` | Можно менять `*p` | Можно менять `p` |
|---|---|---|---|
| `const int* p` | данные | нет | да |
| `int* const p` | сам указатель | да | нет |

- `const int*` — «указатель на константу»: значение по адресу менять нельзя, переприсвоить указатель можно.
- `int* const` — «константный указатель»: адрес фиксирован, значение менять можно.

Примеры:
```cpp
int a = 1, b = 2;
const int* p1 = &a;  // *p1 = 5 — нельзя; p1 = &b — можно
int* const p2 = &a;  // *p2 = 5 — можно; p2 = &b — нельзя
```

### 2. Почему нельзя изменить значение через `const int*`, даже если переменная не `const`?

`const int*` — это обещание **не менять данные через этот указатель**,
которое даёт программист. Компилятор проверяет это на этапе компиляции,
независимо от того, что сама переменная не `const`. Через другие,
не-const указатели её менять по-прежнему можно.

### 3. Можно ли передать неконстантную переменную в функцию с `const int&`?

Да. Это безопасное расширение прав: функция обязуется не менять объект,
а вызывающий ничего не теряет. `const T&` принимает и `const`, и не-`const`
объекты. Обратное (передать `const` туда, где ждут не-`const`) — нельзя.

### 4. Что произойдёт при попытке присвоить новый адрес `int* const`?

Ошибка компиляции: `assignment of read-only variable`. Сам указатель
объявлен константным, его значение (адрес) фиксировано на всю жизнь.
Менять можно только данные по этому адресу.

### 5. Почему `const` в параметрах — хорошая практика?

- Защищает данные от случайного изменения.
- Делает интерфейс понятнее: сразу видно, что параметр только для чтения.
- Позволяет компилятору оптимизировать.
- Позволяет передавать в функцию как `const`, так и не-`const` объекты.

### 6. Что лучше для больших неизменяемых объектов: `const T*` или `const T&`?

`const T&` — предпочтительнее.

- Синтаксис чище (не нужен `*` и проверка на `nullptr`).
- Гарантирует, что объект существует (ссылка не бывает null).
- `const T*` оправдан, только если параметр действительно может
  отсутствовать (`nullptr`).
