# Задание 4. Передача динамического массива в функцию

## 1. Почему при передаче `int* arr` в функцию нельзя изменить сам указатель `data` в вызывающем коде?

В функцию передаётся **копия указателя** (значение адреса). Внутри функции `arr` —
это отдельная локальная переменная. Присвоив ей новый адрес (`arr = ...`),
мы меняем только локальную копию. Оригинальный `data` в `main` остаётся прежним.

## 2. Что означает синтаксис `int*& arr`? Почему он позволяет изменить указатель?

Это **ссылка на указатель**. Функция получает не копию указателя, а ссылку
на оригинальную переменную-указатель в вызывающем коде. Любое присваивание
`arr = ...` внутри функции меняет сам `data` снаружи.

Правило: чтобы изменить переменную в вызывающем коде — принимаем её **по ссылке**.

## 3. Можно ли передать динамический массив «по значению»? Почему?

Строго говоря — нет. В C++ массив нельзя передать по значению в функцию.
При передаче `int* arr` копируется **указатель**, а не массив. Внутри функции
ты работаешь с теми же данными, но не можешь заменить сам массив новым.
Чтобы реально скопировать массив, нужно явно его копировать (например, `std::vector`).

## 4. Что произойдёт, если в `reallocateArray` забыть обновить `size`?

Размер останется старым (3), хотя реально выделено 6 элементов. Дальнейшие
циклы `for (int i = 0; i < size; ++i)` будут обрабатывать только 3 элемента,
а `new int[6]` с 3 заполненными — недоиспользоваться. В других сценариях
это может привести к выходу за границы при попытке обратиться к «лишним»
элементам, если бы код полагался на реальный размер.

## 5. Почему важно освобождать старый массив перед выделением нового в `reallocateArray`?

Иначе старый блок памяти останется недостижимым — на него больше не
указывает ни одна переменная. Это **утечка памяти**. Особенно опасно
в циклах: каждая итерация теряет блок памяти.

Правильно: сначала `delete[] arr`, потом `arr = new int[...]`.

## 6. Какие риски при передаче указателя без размера? Как этого избежать?

Без размера функция не знает, сколько элементов в массиве. Риски:
- выход за границы массива;
- чтение/запись чужой памяти → неопределённое поведение, `segmentation fault`;
- порча данных.

- **всегда передавать размер отдельным параметром**;
- использовать `std::vector` (хранит размер сам);
