# Задание 2. Виды конструкторов `TrackedString`

## Описание

Реализован класс `TrackedString` — обёртка над `std::string`, которая
логирует каждый вызов конструктора, деструктора и оператора присваивания
и поддерживает два статических счётчика: сколько объектов создано
за всё время (`totalCreated`) и сколько существует прямо сейчас
(`aliveCount`).

## Файлы

- `tracked_string.h` — объявление класса `TrackedString`
- `tracked_string.cpp` — реализация
- `main.cpp` — демонстрация работы
- `README.md` — этот файл

## Функции

| Элемент класса | Назначение |
|---|---|
| `TrackedString()` | конструктор по умолчанию |
| `TrackedString(const std::string&)` | конструктор из `std::string` |
| `TrackedString(const char*)` | конструктор из C-строки |
| `TrackedString(const TrackedString&)` | копирующий конструктор |
| `operator=(const TrackedString&)` | копирующее присваивание |
| `~TrackedString()` | деструктор |
| `static int totalCreated()` | счётчик всех созданных объектов |
| `static int aliveCount()` | счётчик живых объектов |
| `const std::string& value()` | доступ к значению |
| `int id()` | уникальный id объекта |

## Ответы на вопросы

### 1. В чём различия между видами конструкторов?

- **По умолчанию** — `TrackedString()`. Создаёт объект с пустой строкой.
  Вызывается, когда объект создаётся без аргументов.
- **Из `std::string`** — `TrackedString(const std::string&)`. Инициализирует
  значение копией переданной строки. Может использоваться для неявных
  преобразований.
- **Из `const char*`** — `TrackedString(const char*)`. Удобен для литералов
  (`"hello"`) и C-строк. Принимает указатель на массив символов и
  копирует его в `std::string`.
- **Копирующий** — `TrackedString(const TrackedString&)`. Создаёт новый
  объект как копию уже существующего. Вызывается, например, при передаче
  по значению или инициализации копией.

### 2. Когда вызывается копирующий конструктор? Примеры. Зачем он нужен?

Копирующий конструктор вызывается, когда **создаётся новый объект
на основе уже существующего**:

1. **Инициализация копией:**
   ```cpp
   TrackedString a("hello");
   TrackedString b = a;      // copy ctor
   TrackedString c(a);       // copy ctor
   ```

2. **Передача объекта в функцию по значению:**
   ```cpp
   void f(TrackedString s);
   f(a);                     // copy ctor
   ```

3. **Возврат объекта из функции по значению** (если не сработал RVO/NRVO).

Нужен он для **корректного копирования внутреннего состояния**
(в нашем случае — строки `value`). Если бы копирующего конструктора не
было, компилятор сгенерировал бы его сам (по умолчанию — почленно), но
у нас собственное поведение: увеличить счётчики и написать в лог.

### 3. Чем копирующий конструктор отличается от оператора присваивания?

- **Копирующий конструктор** — создаёт **новый** объект. Вызывается,
  когда объекта ещё нет.
- **Оператор присваивания** — работает с **уже существующим** объектом,
  у которого просто перезаписывается значение.

Разница в `TrackedString d = c;` vs `a = b;`:
- `TrackedString d = c;` — **инициализация**. `d` ещё не существует,
  поэтому вызывается **копирующий конструктор**.
- `a = b;` — **присваивание**. `a` уже создан, поэтому вызывается
  **оператор `=`**.

Правило: если в объявлении переменной есть тип (`TrackedString d = ...`),
это **инициализация** (конструктор). Если переменной уже существующего
типа присваивается значение (`a = ...`), это **присваивание** (operator=).

### 4. Порядок уничтожения объектов по логу

Из `task02.log`:
```
[dtor] id=4 this=0x... alive=3
[dtor] id=3 this=0x... alive=2
[dtor] id=2 this=0x... alive=1
[dtor] id=1 this=0x... alive=0
```

Деструкторы вызываются в **обратном порядке** относительно создания:

```
Создание:  a(1) → b(2) → c(3) → d(4)
Уничтожение: d(4) → c(3) → b(2) → a(1)
```

Причина — **стек**: локальные объекты живут до конца блока и уничтожаются
в порядке LIFO (last in — first out). Объект `d` создан последним, значит,
первым и разрушится.

### 5. Чем отличаются `totalCreated` и `aliveCount` после блока?

После блока:
```
totalCreated = 4
aliveCount   = 0
```

- **`totalCreated = 4`** — за всю программу было создано 4 объекта.
  Он **не уменьшается** в деструкторе.
- **`aliveCount = 0`** — на данный момент живых объектов нет.
  Он увеличивается в каждом конструкторе и уменьшается в деструкторе.

`aliveCount = 0` говорит о том, что **все созданные объекты корректно
уничтожены**. Это важный признак отсутствия утечек ресурсов на уровне
класса: каждый конструктор был сбалансирован деструктором.
