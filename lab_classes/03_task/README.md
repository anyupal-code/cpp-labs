# Задание 3. Списки инициализации

## Описание

Демонстрация разницы между двумя способами инициализации поля-объекта
в конструкторе: через присваивание в теле (вариант A) и через список
инициализации (вариант B). Разница видна по логам `task03_a.log` и
`task03_b.log`.

## Файлы

- `wrapper.h` — объявления классов `WrapperA` и `WrapperB`
- `wrapper.cpp` — реализации конструкторов
- `tracked_string.h` — копия из `02_task` (без изменений)
- `tracked_string.cpp` — копия из `02_task` (без изменений)
- `main.cpp` — демонстрация двух вариантов с переключением лог-файла
- `README.md` — этот файл

## Функции

| Класс | Конструктор | Стиль инициализации |
|---|---|---|
| `WrapperA` | `WrapperA(const std::string&)` | присваивание в теле |
| `WrapperB` | `WrapperB(const std::string&)` | список инициализации |

## Ответы на вопросы

### 1. Разница в количестве созданных объектов (по логам)

**`task03_a.log` (вариант A):**
```
[default ctor] id=1 alive=1
[string ctor]  id=2 value="hello" alive=2
[copy assign]  id=1 from id=2
[dtor]         id=2 alive=1
[dtor]         id=1 alive=0
```
Создано **2 объекта**: поле `str` (id=1) и временный (id=2).

**`task03_b.log` (вариант B):**
```
[string ctor] id=3 value="hello" alive=1
[dtor]        id=3 alive=0
```
Создан **1 объект** (id=3).

### 2. Почему в варианте A появляется лишний объект и `copy assign`?

В варианте A конструктор `WrapperA::WrapperA(const std::string& s)`
**не содержит списка инициализации**. Значит, поле `str` инициализируется
неявно — **конструктором по умолчанию** `TrackedString()`. Это и есть
первый объект (`default ctor id=1`).

Затем в теле конструктора выполняется `str = TrackedString(s)`:

1. создаётся **временный** объект `TrackedString(s)` (`string ctor id=2`);
2. временный **присваивается** полю `str` через `operator=` (`copy assign id=1 from id=2`);
3. временный **уничтожается** в конце полного выражения (`dtor id=2`).

Итог: 1 объект создан «зря» (default ctor), плюс временный,
плюс лишняя операция присваивания. Всё это — накладные расходы.

### 3. Роль временного объекта

Временный объект — это `TrackedString(s)`, созданный **справа** от знака `=`.

Он существует только на время выполнения полного выражения
(`str = TrackedString(s);`). Как только оператор присваивания завершён,
временный объект больше не нужен и уничтожается в конце выражения —
это и есть `[dtor] id=2 alive=1` сразу после `copy assign`.

### 4. Зависит ли порядок инициализации полей от порядка в списке инициализации?

**Нет.** Порядок инициализации полей определяется **порядком их объявления
в классе**, а не порядком в списке инициализации. Компилятор обычно
предупреждает (`-Wreorder`), если порядок в списке не совпадает
с порядком объявления.

Пример:
```cpp
class Example {
    int b;   // объявлено первым
    int a;   // объявлено вторым
public:
    Example() : a(1), b(2) {}  // инициализируется сначала b, потом a
};
```
Здесь `b` будет инициализирован первым, несмотря на то, что в списке
инициализации `a` указан раньше. Это классическая ловушка.

### 5. Как инициализируются поля, если их не указать в списке инициализации?

- **Поля-примитивы** (`int`, `double`, `bool` и т.п.) — **не инициализируются**
  (остаются с неопределённым значением). Для них нужно либо указать
  значение в списке инициализации, либо присвоить в теле, либо использовать
  `int x = 0;` в объявлении (default member initializer, C++11+).
- **Поля-объекты классов** — инициализируются **конструктором по умолчанию**
  этого класса. Если у класса нет конструктора по умолчанию, объект
  не скомпилируется без явной инициализации в списке.

Именно поэтому для `TrackedString str;` в `WrapperA` вызывается
`default ctor` — мы не указали поле в списке, и компилятор применил
конструктор по умолчанию.
