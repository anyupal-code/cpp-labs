# Задание 5. Перегрузка операторов

## Описание

Для класса `TrackedString` перегружены оператор вывода в поток и операторы
сравнения/сложения. Каждый оператор пишет в лог сообщение о своём вызове.
На примере логов видно, какие операторы вызываются, и как работает RVO
при возврате из `operator+`.

## Ответы на вопросы

### 1. Какие операторы лучше реализовывать как методы класса, а какие — как свободные функции?

**Как методы класса** — операторы, которые **изменяют сам объект** и логически
привязаны к нему:
- `operator=` (присваивание),
- `operator+=`, `operator-=` и т. п. (составные присваивания),
- `operator[]`, `operator()`, `operator*`, `operator->` (доступ).

**Как свободные функции** — операторы, у которых **левый операнд не наш
класс** или **оба операнда равноправны**:
- `operator<<` (левый операнд — `std::ostream`),
- `operator==`, `operator!=`, `operator<` (сравнение двух объектов),
- `operator+`, `operator-` (бинарные арифметические).

**Почему?** Если оператор-метод, он вызывается как `a.operator+(b)`,
то есть `a` обязательно должен быть слева. Для симметричных операций
(сравнение, сложение) это неудобно: хочется `a + b` и `b + a` работать
одинаково. Свободная функция принимает оба операнда как параметры —
симметрично.

### 2. Почему `operator<<` почти всегда свободная функция?

Потому что **левый операнд — `std::ostream`**, а не наш класс. Если
объявить `operator<<` как метод класса, то вызывать его придётся как
`a.operator<<(std::cout)`, а стандартный синтаксис `std::cout << a`
не сработает. Кроме того, `std::ostream` — чужой класс, мы не можем
добавить туда методы.

Поэтому `operator<<` делают **свободной функцией** с сигнатурой:
```cpp
std::ostream& operator<<(std::ostream& os, const TrackedString& ts);
```

А чтобы получить доступ к приватным полям, объявляют её **`friend`**
внутри класса.

### 3. Где требуется `friend` и что он означает?

`friend` нужен, **когда функция или класс должны иметь доступ к приватным
(и защищённым) членам другого класса, но не являются его членами**.

В нашем случае:
- `operator<<` — **friend**, потому что читает `ts.id_` и `ts.value_` —
  приватные поля.
- `operator==`, `operator!=`, `operator<`, `operator+` — **не friend**,
  потому что используют публичные геттеры `id()` и `value()`.

**Что означает `friend`:**
- даёт функции доступ к `private` и `protected` членам класса;
- `friend`-функция **не является** методом класса (не имеет `this`);
- `friend` не наследуется и не транзитивен;
- использовать `friend` стоит **минимально**: каждый `friend` ослабляет
  инкапсуляцию. Если можно обойтись публичным интерфейсом — обходимся.

### 4. Сколько объектов создаётся при `auto c = a + b;`? Есть ли копирующий конструктор при возврате? Что такое copy elision (RVO)?

По логу `task05.log`:

```
[operator+] id=1 + id=2
[string ctor (target)] id=3 value="helloworld" alive=3
[operator<<] id=3
[dtor] id=3
[dtor] id=2
[dtor] id=1
```

При выполнении `auto c = a + b;` создаётся **ровно один** объект —
`id=3` со значением `"helloworld"`. **Копирующего конструктора нет** —
в логе **нет** строки `[copy ctor]` для `id=3`.

Почему? Потому что компилятор применил **RVO (Return Value Optimization)** —
одну из форм **copy elision**. Суть: возвращаемый из функции объект
конструируется **прямо в том месте**, где он должен быть использован
(в переменной `c`), минуя создание временного объекта и его копирование.

**Начиная с C++17 RVO для prvalue стало обязательным**: если функция
возвращает временный объект по значению, компилятор **не имеет права**
делать копирование или перемещение — он обязан сконструировать результат
прямо на месте вызова.

**Итог:** в C++17+ `TrackedString operator+(...)` **не создаёт лишних
копий** при возврате — при условии, что возвращается именно локальный
объект (prvalue) и тип совпадает.

Это делает цепочки вида `a + b + c + d` эффективными: каждый `operator+`
создаёт ровно один объект.
