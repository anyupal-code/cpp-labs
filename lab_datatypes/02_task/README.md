# Задание 2. Переполнение целочисленных типов

## Часть 1. Беззнаковое переполнение (`uint32_t`)

`UINT32_MAX` = `4294967295` = `0xFFFFFFFF`:

```
11111111 11111111 11111111 11111111
```

Операция `UINT32_MAX + 2`:

```
  11111111 11111111 11111111 11111111   (0xFFFFFFFF)
+ 00000000 00000000 00000000 00000010   (0x00000002)
─────────────────────────────────────
1 00000000 00000000 00000000 00000001   (0x1_00000001)
```

Старший бит (33-й) выходит за пределы 32-битной разрядной сетки и **отбрасывается**. Остаётся:

```
00000000 00000000 00000000 00000001
```

Это число `1`.

**Вывод:** `UINT32_MAX + 2 == 1`.

## Часть 2. Знаковое переполнение (`int32_t`)

`INT32_MAX` = `2147483647` = `0x7FFFFFFF`:

```
01111111 11111111 11111111 11111111
```

Старший бит = `0` → число положительное.

Операция `INT32_MAX + 2` (вычисление выполнено в `uint32_t`, затем приведено к `int32_t`):

```
  01111111 11111111 11111111 11111111   (0x7FFFFFFF)
+ 00000000 00000000 00000000 00000010   (0x00000002)
─────────────────────────────────────
  10000000 00000000 00000000 00000001   (0x80000001)
```

Старший бит стал `1`. Для `int32_t` это означает **отрицательное** число в дополнительном коде. Значение:

```
−2^31 + 1 = −2147483647
```

**Вывод:** `INT32_MAX + 2 == −2147483647`.

## Вопрос 1. Объясните результат `UINT32_MAX + 2`

`UINT32_MAX` — максимальное значение беззнакового 32-битного типа — все 32 бита равны `1`:

```
UINT32_MAX = 11111111 11111111 11111111 11111111 = 0xFFFFFFFF
```

Прибавляем `2` (`0x00000002`):

```
  11111111 11111111 11111111 11111111
+ 00000000 00000000 00000000 00000010
─────────────────────────────────────
1 00000000 00000000 00000000 00000001
```

В 32-битной сетке помещается только младшие 32 бита: `00000000 00000000 00000000 00000001` = `1`. «Лишний» старший бит (переполнение) **отбрасывается**, потому что арифметика беззнаковых чисел выполняется **по модулю `2^32`**:

```
(UINT32_MAX + 2) mod 2^32 = (2^32 − 1 + 2) mod 2^32 = 1
```

## Вопрос 2. Объясните результат `INT32_MAX + 2`

`INT32_MAX` — максимальное значение знакового 32-битного типа:

```
INT32_MAX = 01111111 11111111 11111111 11111111 = 0x7FFFFFFF
```

Старший бит = `0` (число положительное), остальные 31 бит = `1`.

Прибавляем `2`:

```
  01111111 11111111 11111111 11111111   (INT32_MAX)
+ 00000000 00000000 00000000 00000010   (2)
─────────────────────────────────────
  10000000 00000000 00000000 00000001   (0x80000001)
```

Произошёл «перенос» через все младшие биты: `0x7FFFFFFF + 1 = 0x80000000`, ещё `+1 = 0x80000001`. Старший бит (знаковый) стал равен `1`, что означает **отрицательное** число в дополнительном коде.

Значение `0x80000001` в дополнительном коде как `int32_t`:
- Инверсия: `01111111 11111111 11111111 11111110`
- +1: `01111111 11111111 11111111 11111111` = `2147483647`
- Значит, исходное число = `−2147483647`.

Проверка «обратным счётом»: `0x80000000 = −2^31 = −2147483648`, значит `0x80000001 = −2147483647`.

## Вопрос 3. Почему переполнение беззнаковых безопасно, а знаковых — нет?

**Беззнаковые типы.** Стандарт C++ (§6.9.1/4) определяет арифметику беззнаковых чисел как **модульную**:

> «Unsigned integers, declared unsigned, shall obey the laws of arithmetic modulo 2^n where n is the number of bits in the value representation of that particular size of integer.»

То есть результат `UINT32_MAX + 2` **гарантированно** равен `1` — это описано в стандарте, воспроизводимо на любой платформе, и компилятор не имеет права «сойти с ума». Такое поведение используется на практике: хеши, кольцевые буферы, счётчики, криптография.

**Знаковые типы.** Для знаковых чисел переполнение в C++ — это **undefined behavior (UB)** (§6.9.1/1, §7.1.4). Формально:

> «If during the evaluation of an expression, the result is not mathematically defined or not in the range of representable values for its type, the behavior is undefined.»

Что это значит на практике:
- Компилятор может **предполагать**, что переполнения не происходит, и строить оптимизации на этом.
- Например, для `int x = INT_MAX; if (x + 1 < x) {...}` компилятор с `-O2` может решить, что условие **никогда** не истинно, и просто **убрать** ветку `if`.
- Программа может выдать любой результат: правильный, неправильный, зависнуть или упасть.
- В отличие от беззнакового, знаковое переполнение **не даёт** «предсказуемого обнуления» — оно вообще ничего не гарантирует.

Поэтому в нашем коде мы вычисляли `INT32_MAX + 2` через промежуточный `uint32_t`, чтобы избежать UB прямо в выражении сложения.

## Вопрос 4. Что говорит стандарт C++ о переполнении знаковых целых?

Стандарт C++ (ISO/IEC 14882, раздел «Expressions» / «Fundamental types») говорит:

- **Знаковое переполнение — undefined behavior.** Это означает, что стандарт **не накладывает никаких требований** на поведение программы при переполнении `int`, `int32_t` и т.п. Компилятор вправе генерировать любой код.
- **Беззнаковое переполнение — well-defined.** Результат всегда вычисляется по модулю `2^n`, где `n` — число бит в представлении типа.

В C++20 и C++23 формулировки уточнялись, но суть та же: signed overflow — UB, unsigned overflow — модульная арифметика.

Историческая причина: на разных платформах знаковые числа могли представляться по-разному (прямой код, обратный код, дополнительный код), и стандарт не хотел привязываться к конкретной реализации. Сейчас практически везде используется дополнительный код, и в C++20 даже зафиксировали, что `int` — two's complement, но правило про UB для переполнения **сохранили** — чтобы компиляторы могли оптимизировать.
